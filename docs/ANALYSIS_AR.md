# تحليل وتحويل تصميم علوان للعطور إلى React Native وNestJS

## 1) تحليل واجهة HTML الأصلية

الملف المرجعي: `docs/reference-design.html`. كانت النسخة عبارة عن تطبيق ويب محلي، يحفظ مصفوفات العملاء والمشتريات في `localStorage` بدون هوية مستخدم للخادم أو قاعدة بيانات. تبدأ الواجهة العربية RTL من شاشة «شراء جديد»، وتحتوي على خمسة مسارات أساسية: الرئيسية، العملاء، المشتريات، ملف العميل، تحليلات الذوق. لا يوجد تبويب إعدادات، وفق قرار صاحب المشروع.

**هوية التصميم التي تم الاحتفاظ بها:** كريمي `#F7F2EE`، بطاقات فاتحة `#FFFAF7`، بني داكن `#302724`، ذهبي `#A9793D`، وردي `#A76B70`، خط **Almarai**، صور حقيقية للنوتات، صورة الزهرة أعلى الصفحات وزخرفة القائمة الجانبية. صور التصميم المرجعي أعيد استخدامها بعد تصديرها بصيغة PNG/JPEG كملفات محلية داخل تطبيق الهاتف لتجنب اعتماد وقت التشغيل على خدمات صور أو CSS/HTML/WebView.

## 2) تدفق العمل المعتمد

1. صاحب المحل يسجّل دخوله إلى تطبيق التابلت/الهاتف (حساب إداري واحد في نسخة MVP).
2. يضيف العميل باسمه ورقم هاتفه الدولي. الرقم فريد؛ يمنع إنشاء عميل ثانٍ بنفس الرقم.
3. يسجل عملية شراء: العميل، اسم العطر، التاريخ، التقييم (1..5)، نوتة رئيسية، ونوتة واحدة أو أكثر موجودة في العطر.
4. يحدد النوتات التي يحبها العميل عادةً (قد تختلف عن نوتات العطر المشترى). إذا تركها دون تغيير تبقى كما كانت.
5. يفتح ملف الزبون ويشاهد جميع مشترياته وتواريخها والتقييم والنوتات.
6. يفتح تحليلات الذوق لذلك الزبون أو يختار زبونًا آخر في صفحة التحليلات.
7. عند مشاركة الملخص يفتح WhatsApp برسالة مقروءة تحتوي على سجل المشتريات وأهم النوتات. الإرسال يدوي بعد مراجعة الرسالة، وليس إرسالًا جماعيًا أو تلقائيًا.

## 3) خريطة الشاشات والمكونات

| الشاشة | المكونات | مصدر البيانات |
|---|---|---|
| تسجيل الدخول | اسم المستخدم/كلمة المرور | `POST /auth/login` |
| الرئيسية | صورة عطر، بطاقات KPI، آخر العمليات | `GET /dashboard` |
| العملاء | بحث، بطاقة العميل، إضافة عميل وتفضيلاته | `GET/POST /customers` |
| ملف العميل | المشتريات، تفاصيل كل عملية، تعديل التفضيلات، واتساب | `GET/PATCH /customers/:id/...` |
| المشتريات | سجل وبحث، بطاقة لكل عملية | `GET /purchases` |
| شراء جديد | حقول العملية، تقييم النجوم، شبكة الصور للنوتات، النوتة الرئيسية، ملخص حي | `POST /purchases` |
| تحليلات الذوق | اختيار عميل، أعلى النوتات تقييمًا وأكثرها شراءً، التفضيلات المباشرة | `GET /customers/:id/analytics` |

### قواعد تصميم الموبايل

- الشاشة الرئيسية والمكونات تطبق RTL حقيقي، ولا يتم تحويل HTML إلى WebView.
- **≥860px** قائمة جانبية على اليمين؛ **<860px** شريط تنقل علوي قابل للتمرير.
- صور الخلفية داخل Layout مشترك لكل الشاشات، لا قواعد CSS تخفيها على الموبايل.
- نوتات العطر بطاقات مصوّرة مع اختيار متعدد واضح، وأخطاء الإدخال مرئية.
- الجداول الطويلة تُعرض كبطاقات، لمنع التمرير الأفقي الكاسر للتصميم.
- صور النوتات محلية وخفيفة (مجموعها أقل من 100KB تقريبًا) ولا يوجد BlurView أو `backdrop-filter`.

## 4) نموذج قاعدة البيانات

- **OwnerUser**: حساب المالك (اسم مستخدم، كلمة مرور مشتقة بـscrypt، لا نص صريح).
- **Customer**: اسم، هاتف فريد، مشتريات، نوتات مفضلة.
- **FragranceNote**: قاموس النوتات (مثل ورد، عود، مسك، فانيلا).
- **Purchase**: العميل، اسم العطر، تاريخ الشراء، التقييم 1–5، النوتة الرئيسية.
- **PurchaseNote**: ربط M:N بين كل عملية شراء والنوتات الموجودة في العطر؛ منع التكرار بمفتاح مركب.
- **CustomerFavoriteNote**: ربط M:N منفصل بين العميل والنوتات التي يصرح بأنه يحبها.

**ضروري:** لا تستخدم التفضيلات مباشرة لاستنتاج النوتة الأكثر شراءً؛ ولا تحسب النوتة المشتركة في عدة عطور مرتين ضمن *العملية الواحدة*.

## 5) المعادلات الخاصة بكل عميل

عند النظر إلى العميل C والنوتة N:

- `purchaseCount(C,N)`: عدد عمليات شراء C التي تحتوي على النوتة N.
- `avgStars(C,N)`: مجموع تقييمات مشتريات C التي تحتوي على N ÷ عدد تلك المشتريات.
- `mostPurchased(C)`: ترتيب نوتات C تنازليًا حسب عدد المشتريات.
- `mostLiked(C)`: ترتيب نوتات C تنازليًا حسب متوسط النجوم، ومع التعادل يقدم الأكثر شراءً.
- `favoriteNotes(C)`: قائمة مستقلة يحددها العميل ولا تدخل في خوارزمية المتوسط.

**محدودية إحصائية:** نوتة تم شراؤها مرة بتقييم 5 قد تتصدر المتوسط على نوتة حصلت على متوسط 4.8 عبر 10 مشتريات. لذلك تعرض الواجهة عدد مرات الشراء بجانب المتوسط، ويُنصح لاحقًا بمؤشر ثقة عند كثرة البيانات.

## 6) اعتبارات أمنية وتشغيلية

- JWT على جميع المسارات ما عدا `auth/login` و`health`؛ ينتهي بعد 12 ساعة.
- تخزين رمز دخول المالك في `expo-secure-store` على الأجهزة الأصلية.
- كلمات مرور المالك مشتقة بـscrypt وتُدخل بواسطة متغيرات بيئة أثناء إنشاء الحساب.
- إدخال البيانات يتم التحقق منه عبر DTO و`ValidationPipe` مع منع الحقول غير المعروفة.
- حماية أساسية من تكرار محاولات تسجيل الدخول (داخل عملية السيرفر). على الإنتاج أضف reverse-proxy rate limiting وسجلات تدقيق ونسخًا احتياطية.
- لا توجد حسابات للزبائن؛ الرقم يستخدم للربط والمشاركة فقط. يجب حماية بيانات أرقام العملاء وفق قوانين الخصوصية ذات الصلة.
- لا إرسال تلقائي لواتساب. مالك الحساب يراجع النص في تطبيق WhatsApp قبل الإرسال.
- الاتصال المحلي HTTP للتطوير فقط؛ الإنتاج يجب أن يستخدم HTTPS.

## 7) نطاق النسخة الحالية وما يلزم للإنتاج

**موجود في كود البداية:** شاشات React Native أصلية، الصور والزخارف، تبويب التحليلات الخاص بالعميل، تسجيل الدخول، API وPrisma migration، seed، إضافة العملاء والمشتريات، تعديل التفضيلات، رسالة واتساب، اختبارات لوظيفة حساب المتوسط.

**لم يُنجز بعد:** تثبيت الحزم وبناء APK على جهاز فعلي، اختبار تكاملي مع PostgreSQL حقيقي، التحقق من الأداء مع آلاف العملاء، تنقيح دقيق لكل جهاز مقارنة بلقطات المرجع، إدارة موظفين وصلاحيات متعددة، سياسة نسخ احتياطي واسترجاع، إعادة تعيين كلمة المرور، سجلات تدقيق. هذه أعمال مستقلة مطلوبة قبل تسليم تطبيق إنتاجي.
